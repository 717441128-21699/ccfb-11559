# levelcheck —— 平台跳跃关卡通关静态校验工具

在关卡提交前自动检查"这关能不能通关":根据角色的跑速、起跳初速、重力、
土狼时间、二段跳,算出所有能落脚的位置;把够不着的收集品和终点单独列出;
移动平台按往返周期算出什么时候跳上去才赶得上。

- **百屏关卡 < 10 秒**(实测 2000×18 格、含 10 个移动平台与弹簧,约 7 秒)
- **落点与游戏实测偏差 ≤ 半格**:分析器与游戏侧调用同一个物理积分函数
- 输出中文终端报告、CI 用 JSON、评审用 Markdown;退出码可直接接门禁

## 为什么落点能保证不超过半格

分析器**没有重新实现一套物理**。`levelcheck/simulate.py` 里的 `step()`
是唯一的物理事实来源,固定 60Hz 半隐式欧拉积分:

- 真实游戏的角色脚本调用 `step()` 推进每一帧;
- 静态分析器枚举一组跳跃策略后,也是反复调用同一个 `step()` 跑弧线。

两边用的是同一份函数、同一套常数(`physics.py`),落点不可能两边跑偏。
报告里的每个落脚点 y 都精确落在瓦片/平台/弹簧顶面上(整数格线或平台位姿),
偏差来源只剩起跳槽位离散化,且目标判定用的是模拟产生的**真实落地坐标**。
测试 `tests/test_analyzer_sim_parity.py` 结构性断言 `analyzer.step is simulate.step`。

## 安装与运行

纯 Python 标准库实现,无第三方依赖(Python 3.10+):

```bash
# 单个关卡,中文报告
py -m levelcheck levels/level_1_1_basic.json

# CI 门禁:机器可读 JSON
py -m levelcheck levels/level_1_1_basic.json --json

# 写 Markdown 评审报告
py -m levelcheck levels/level_1_3_moving.json --md -o review.md
```

退出码:

| 码 | 含义 |
|----|------|
| 0  | 通过:终点 + 全部收集品可达 |
| 2  | 关卡可解析,但存在不可达目标 |
| 3  | 关卡数据不合法 / 分析超时 / 平台联合周期超限 |

### 生成百屏压测关卡

```bash
py tools/gen_perf_level.py     # 写出 levels/perf_100.json(2000×18)
py -m levelcheck levels/perf_100.json
```

## 关卡 JSON 格式

```jsonc
{
  "name": "1-1",
  "bounds": {"width": 24, "height": 12},
  "physics": { /* 可选,覆盖默认角色参数 */ },
  "spawn": {"x": 1.5, "y": 11.0},   // 角色脚底中心
  "goal":  {"x": 22.5, "y": 11.0},   // 终点中心(脚底线)
  "rows": ["####", "...."],          // '#' 实心瓦片
  "solid_tiles": [[3, 4]],           // 也可直接给瓦片坐标
  "springs":   [{"x": 7, "y": 10.5, "width": 1, "height": 0.5}],
  "platforms": [{
    "id": "lift", "x": 12, "y": 9, "width": 3, "height": 0.5,
    "axis": "y", "amplitude": -4, "period_frames": 120,
    "phase_frames": 0, "motion": "triangle"
  }],
  "hazards":      [{"x": 16, "y": 11.5, "width": 2, "height": 0.5, "kind": "spike"}],
  "collectibles": [{"id": "c1", "x": 7, "y": 4.2, "radius": 0.4}]
}
```

坐标系原点在左上角,x 向右、y 向下,单位为格(默认 32px)。
移动平台 `amplitude` 带符号:y 轴平台负值表示向上运动(基准点即最低位)。

### 默认角色物理(可在 physics 段覆盖)

| 参数 | 默认值 | 说明 |
|------|--------|------|
| run_speed | 6.0 格/秒 | 满跑速 |
| jump_velocity | 12.5 格/秒 | 起跳初速(向上) |
| gravity | 36 格/秒² | 重力 |
| coyote_time | 0.10 秒 | 土狼时间(6 帧) |
| max_air_jumps | 1 | 二段跳次数 |
| air_jump_velocity | 11.0 格/秒 | 二段跳初速 |
| spring_velocity | 19.0 格/秒 | 弹簧弹射初速 |

满跳离散高度 2.275 格、滞空约 43 帧,公式见 `physics.PhysicsConfig.full_jump_height()`。

## 分析器工作原理

1. **表面提取**:实心瓦片/弹簧顶面合并成连续可站立表面,按规范起跳位分槽。
2. **跳跃弧线枚举**:每个起跳位枚举满跳、短跳、小跳、三档二段跳、弹簧弹射,
   左右两个方向,每条弧线直接调用 `step()` 模拟。
3. **落脚点 BFS**:静态落脚点 + 移动平台落脚点(id × 相位),FIFO 求最早可达帧,
   记录父节点链以输出可复现的操作路径。
4. **移动平台节拍**:等待边逐帧连接平台的所有相位(任意相位都能站立),
   起跳弧线在采样相位枚举;几何拦截求"哪些相位会在哪一帧接住角色",
   报告给出可搭乘相位窗口与最早搭乘帧。
5. **目标判定**:终点/收集品用模拟产生的真实落地坐标 + 弧线飞行触碰双重判定,
   不可达项附最近落脚点距离,方便策划定位。

性能工程:空间列散列索引(平台/危险物/弹簧/收集品 O(1) 邻域查询)、
静态/移动弧线缓存、平台中心站位归并、起跳相位采样、热路径标量边界碰撞。

## 能力边界(诚实声明)

- 枚举的是**离散跳跃策略集合**,覆盖正常通关所需输入;逐帧变向等极限 TAS
  操作不在建模范围内。分析器说"可达"是构造性证明(给出动作序列),
  说"不可达"是相对于这套策略集合——若游戏允许更极端操作,需扩 `JUMP_ACTIONS`。
- 移动平台联合周期(LCM)上限 3600 帧(60 秒),超过会要求策划调整周期,
  避免相位组合爆炸。
- 平台运动轨迹撞进实心瓦片会在结构校验阶段直接报错(物理行为未定义)。
- 静态目标的可达性基于表面规范起跳位;落点本身仍是全精度模拟坐标。

## 目录结构

```
levelcheck/
  physics.py    物理常数与离散/解析公式
  level.py      关卡 JSON 模型、空间索引、结构自检
  simulate.py   角色状态机 + 固定步长碰撞积分(游戏侧共用)
  analyzer.py   落脚点 BFS、弧线枚举、移动平台相位分析
  report.py     文本 / JSON / Markdown 渲染
  cli.py        命令行入口
levels/         示例关卡(含不可达收集品回归用例)
tests/          物理一致性、落点偏差、可达性场景、性能、CLI
tools/          百屏压测关卡生成器、调试脚本
```
