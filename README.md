# levelcheck — 平台跳跃关卡可通关性检查器

关卡提交前的自动检查: 按角色的**跑速、起跳初速、重力、土狼时间、二段跳**算出所有能
落脚的位置, 把**够不着的收集品和终点**单独列出来; 移动平台按往返周期给出**什么时候
起跳才落得上**的 timing 窗口。

- 100 屏关卡查完约 **4 秒**(指标 10 秒)
- 落点预测与游戏同语义积分器, 与"实测"偏差 **0**(指标 ≤ 半格; 见下文精度说明)
- 检查不通过时退出码为 1, 可直接接入提交钩子 / CI / 编辑器按钮

## 用法

```bash
# 检查关卡(物理参数缺省用内置默认值)
py -m levelcheck check 关卡.json --physics 物理.json

# 机器可读报告(供编辑器内嵌展示)
py -m levelcheck check 关卡.json --physics 物理.json --json report.json

# 自定义时间预算(默认 10 秒, 超时给出部分结果并标注)
py -m levelcheck check 关卡.json --time-budget 10
```

退出码: `0` 可以通关(终点可达且所有收集品可达), `1` 不可通关, `2` 输入文件错误。

**编辑器集成**: "检查"按钮 → 把当前关卡导出为下述 JSON → 调上面的命令 →
按退出码亮红绿灯, 把 `--json` 报告里的 `unreachable_collectibles` 在编辑器里高亮定位。

## 关卡 JSON 格式

单位均为格(tile), y 轴向上, 角色位置指脚底中心。

```jsonc
{
  "name": "level-07",
  // 方式一: 字符网格(第一行是最上面一行)
  "grid": [
    "########",
    "#......#",
    "#S....G#",
    "########"
  ],  // '#'实心  'S'出生点  'C'收集品  'G'终点  '^'弹簧(默认冲量)
  // 方式二: 结构化对象(可与其网格混用)
  "platforms": [{"x": 0, "y": 0, "w": 8, "h": 1}],        // 实心矩形
  "moving_platforms": [{
    "id": "m1", "x": 10, "y": 3, "w": 2, "h": 0.5,
    "path": [[16, 3]],     // 折线路点(绝对坐标), 匀速往返
    "period": 4.0          // 往返周期(秒)
  }],
  "springs": [{"x": 5, "y": 1, "impulse": 24}],           // 弹簧(可覆盖默认冲量)
  "collectibles": [{"id": "c1", "x": 6, "y": 4, "radius": 0.5}],
  "goal": {"x": 14, "y": 1, "w": 1, "h": 2},
  "spawn": {"x": 1.5, "y": 1}
}
```

## 物理参数 JSON

```jsonc
{
  "run_speed": 8.0,            // 跑动速度(格/秒)
  "jump_velocity": 14.0,       // 起跳初速
  "gravity": 30.0,             // 重力加速度
  "coyote_time": 0.1,          // 土狼时间(秒): 离开边缘后仍可起跳的宽限
  "double_jump": true,         // 是否允许二段跳
  "double_jump_velocity": 12.0,
  "tick_rate": 60,             // 物理帧率(必须与游戏一致!)
  "max_fall_speed": 25.0,
  "player_height": 0.9,        // 顶头判定
  "spring_impulse": 22.0,      // 默认弹簧冲量
  "max_flight_time": 10.0      // 单条轨迹模拟时长上限
}
```

## 输出说明

```
=== 关卡可通关性检查: level-07-事故复现 ===
结论: ✗ 不可通关
终点: 可达
收集品: 2/3 可达
  够不着的收集品:
    - c_hidden @ (21.5, 9.5)  距最近可到达站立面 8.5 格
移动平台起跳时机:
    - m1: 周期 4.00s, 在 0.00s–0.05s, 0.58s–4.00s 起跳可落上(从 站立面 (0.0~10.0, y=1.0))
统计: 站立面 4/6, 模拟轨迹 3045, 用时 0.07s
```

- **够不着的收集品**: 三种够得着的方式都判定失败才会列出 —— 站在可达平台上够到、
  跳跃/坠落弧线经过、乘移动平台经过。
- **移动平台起跳时机**: 按平台往返周期给出的起跳相位窗口(秒)。窗口边界模糊约
  ±1 物理帧(0.5 格容差语义), 与逐帧暴力穷举的一致率 > 95%。

## 算法与精度

1. **轨迹模板**: 起跳 / 二段跳(接续时机按帧采样) / 走出边缘坠落 / 土狼起跳 /
   土狼接二段跳, × 水平速度采样(±100%, ±50%, 0) × 起跳点采样(0.5 格步长)。
2. **批量模拟**: numpy 向量化固定步长积分器, 逐 tick 语义与游戏运行时完全一致
   (跳跃事件→重力→水平移动撞墙→垂直移动落地/顶头/弹簧), 因此预测落点与实测
   偏差为 0; 测试中用独立编写的参考积分器交叉验证 ≤ 0.5 格。
3. **可达性 BFS**: 站立面 → 轨迹 → 新站立面, 迭代至不动点; 移动平台用
   "相位位图"反解起跳窗口, 已到达平台按周期采样产生新起跳点, 支持多平台接力。
4. **收集品**: 站立面邻近 → 乘移动平台 → 弧线经过(标准弧线包络筛选 + 参考
   积分器精确验证, 不漏报不误报)。

## 已知限制(需要时再扩)

- 移动平台不传递速度给角色(起跳不继承平台速度); 平台只沿折线匀速往返。
- 角色碰撞简化为脚底点 + 头顶点(无侧向半身宽判定)。
- 弹簧连锁(弹簧弹到弹簧)在收集品弧线判定中只计一级。
- 空中变向(空中加速度)不建模, 水平速度在起跳时刻采样后保持不变。
